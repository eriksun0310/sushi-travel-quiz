# 壽司旅人

日本旅遊人格測驗：16 題四軸計分，算出 16 種「壽司旅人」。
結果頁最後接上壽司日檢的 26 種壽司收集牆 —— 橋不是內容，是壽司本身。

## 跑起來

```bash
pnpm install
cp .env.example .env.local   # 填 NEXT_PUBLIC_APP_STORE_URL
pnpm dev
```

## 路由

| 路徑 | 說明 |
| --- | --- |
| `/` | 首頁。帶 `?from=<code>` 時顯示邀請人的型別 |
| `/quiz` | 從 27 題題庫每軸抽 4 題，純 client state |
| `/r/[code]` | 結果頁。16 個代碼各自靜態產生，帶 `?from=` 時顯示兩人組合 |
| `/r/[code]/opengraph-image` | 每一型的 OG 圖（next/og，1200×630） |
| `/types` | 16 型一覽 |

## 代碼怎麼讀

四碼，順序同 `src/content/axes.ts` 的 `AXES`：

| 位置 | 軸 | `1` | `0` |
| --- | --- | --- | --- |
| 0 | 規劃 | 表格派 | 隨便走派 |
| 1 | 消費 | 克制 | 失手 |
| 2 | 社交 | 敢開口 | 比手畫腳 |
| 3 | 動機 | 打卡收集 | 體驗沉浸 |

`'0000'` = 隨便走 × 失手 × 比手畫腳 × 沉浸 = 大トロ。

## 壽司怎麼配

**敢花的拿高級壽司。** 消費軸決定貴賤，動機軸決定是「少而精」還是「多而雜」：

| | 沉浸（少而精） | 打卡（多而雜） |
| --- | --- | --- |
| 敢花 | N1 頂級 | N2 中高 |
| 省 | N5 樸素 | N4 大眾 |

N 等級**不會出現在畫面上**，它只決定 `LEVEL_COLORS` 的卡片配色 —— 使用者看到深紫黑的卡就知道自己抽到高級的。
N3 那一排測驗永遠抽不到，只有 App 的圖鑑裡有。

## 出題規則

- 一題只量一個軸，選項是**動作**不是心情，四個選項沒有正確答案
- 選項人格固定：**A** 誇張的準備過頭 → **B** 正常的正端 → **C** 負端但有藉口 → **D** 擺爛但理直氣壯
- **笑點永遠在 D。** 寫新題先寫 D
- **零日文。** 要提到日文就用描述的：「店員用日文問你要幾個」
- 各軸的題材範圍：規劃＝時間與順序、消費＝掏錢、社交＝跟陌生人發生關係、動機＝停留多久

題庫在 `src/content/questions.ts`，27 題（規劃 6 / 消費 10 / 社交 6 / 動機 5）。
消費軸池子最深，所以重測時消費題的差異最大 —— 那也是最好笑最好傳的一軸。

## 文案放哪

全部在 `src/content/`，沒有 CMS、沒有後端：

- `questions.ts` — 題庫與每個選項的權重
- `types.ts` — 16 型的型名、標籤、吐槽
- `poles.ts` — 八個極端各一份維度文案（金句 / 長文 / 口頭禪），16 型由此組合
- `pairing.ts` — 旅伴配對的說明句（目前是公版，待手寫）
- `catalog.ts` — App 的 26 種壽司，收集牆用
- `levels.ts` — 沿用 App 的 `levelColors`

## 邀請機制

沒有後端。`/?from=<code>` 把邀請人的型別帶在網址裡，
對方測完後在自己的結果頁看到兩人組合，再用 Web Share / 剪貼簿把連結傳回去。
